# radiogram 市場探索 & 刺さるデモ設計

- 対象プロダクト: **radiogram**（MLR-429 / 429MHz LoRa・FSK / USB-serial 経由で生成AI(MCPクライアント)同士がテキスト交信する MCP サーバー兼 CLI）
- 作成日: 2026-07-01
- ステータス: ブレインストーミング結果の確定版（国内スタート）

---

## 1. 戦略の芯（合意事項）

- **目的**: (A) 事業化できる市場を探す ＋ (B) 営業・展示で刺さるデモを作る。
- **地域方針**: **国内(A)から始めて → 海外(C)へ展開**。
  - 海外展開時にバンドを再検討（下記「バンド戦略」）。まず国内で既存 MLR-429 のままソフト価値を検証する。
- **プロダクトの芯（価値提案）**:
  > 電波が弱い/届かない拠点で、AI同士が「要約して」交信し、現場判断を分担する。
  > **平常時から毎日使う業務ツールであり、災害時は同じ仕組みが自動的に非常通信網になる。**

> 方針アップデート（2026-07-01）: 「災害時しか使えない」道具は予算が付きにくく、普段使わないので“いざ動かない”。
> そこで **平常時ユース（案A）を主**に据え、災害対策はその延長（内包）として位置づける。

### 評価軸（市場を選ぶ基準）
- 誰がお金を払うかが明確
- 通信インフラが弱い/使えない現場がある
- AI同士が現場判断を分担する必然性がある
- 展示デモで「ネット無しでAIが交信した」が一瞬で伝わる
- MLR-429/radiogram の強み（長距離・省電力・オフグリッド）が差別化できる

### バンド戦略（将来メモ）
- **国内**: 429MHz（日本の免許不要運用想定 / 技適は要確認）＝ 既存ハードで即デモ・即検証。
- **海外・長距離維持**: **sub-GHz LoRa**（868MHz EU / 915MHz 米豪 / 923MHz アジア）が本命。SKUは地域別。
- **2.4GHz化**: 世界共通・免許不要・高速・小型アンテナが利点。ただし**長距離/回り込みという最大の差別化が弱まり**、Wi-Fi/BTと混雑・競合するため、「長距離オフグリッド」を売りにするなら非推奨。海外展開時に用途で選ぶ（先に決め打ちしない）。

---

## 2. 平常時ユース（案A: 恒常的“圏外拠点”の日常運用）

**基本思想**: 平常時から電波が弱い/届かない拠点で「毎日使う」業務ツールにする。毎日使うから訓練不要・機器が生きており、災害時は同じ設置ベースがそのまま指揮系統（非常通信網）になる。防災は“無料の付加価値”。

### 狙う日常現場（常時＝準オフグリッド）
- 農場・牧場・林業（広域圃場、放牧地、山林）
- 山小屋・離島・キャンプ場・山岳施設
- 建設現場・砂防/河川/ダム/治山などの遠隔監視拠点
- 太陽光発電所・鉄塔・変電/ポンプ場などの無人設備
- 大規模イベント/レース会場（回線が混雑・不足する場所）

### 平常時の使い方（毎日のROI）
- **現場AI → 基地AIへ日次要約報告**: 見回り・センサ・作業状況を要約して送信（自然文でOK）。
- **基地AI → 現場AIへ指示/問い合わせ**: 作業指示、確認、優先度づけ。
- **異常だけ通知（テレメトリ内包）**: 常時データはローカルAIが判断し、要点/異常のみ低帯域で送る（＝案Bのテレメトリ機能を取り込み）。
- **通信費ゼロ運用**: SIM/月額なし、電池駆動。ランニングコスト削減が平常時の購入理由になる。

### 平常 → 有事への“自動転用”
- 同じ端末・同じ設置で、シナリオ（プロンプト/テンプレ）を「災害モード」に切替えるだけ。
- 平常時に毎日通信しているため、有事に「つながらない/使い方を忘れた」が起きない。

### この位置づけの利点
- **予算**: 日常業務の効率化・通信費削減（OPEX）で買える。防災は付加価値。
- **維持**: 毎日使う＝常時ヘルスチェック。防災無線の“いざ動かない”問題を解決。
- **説得力**: ROIが平常時に出るので、災害デモの“掴み”と両立できる。

## 3. デモ設計

### ヒーローデモ（まずこれ1本）: 「圏外AI会議」
- 内容: Wi-Fi/LTEを物理的に切った2台（PC / Raspberry Pi）で、AIエージェント同士が MLR-429 越しに相談し結論を出す。画面に「ネット接続:OFF / 電波送信中」を大表示。
- 刺さるポイント: “インターネット無しでAIが会話した”が3秒で伝わる。展示会・営業の掴み。
- 見せ方のコツ: 機内モード/LANケーブル抜きを目の前で実演。送受信ログと距離（別室・屋外）を見せる。低速19200bpsでも成立する理由＝**AIが要点だけ要約して送る**、という物語にする。

### 平常時デモ（案Aの日常運用を1本で見せる）: 「毎日使う圏外拠点」
- 内容: 「農場/現場の端末」と「母屋/事務所の端末」を用意。現場AIが日次の見回り・状況を要約報告 → 事務所AIが確認・指示。SIM/Wi-Fi無しで往復。
- 締めの一手: そのまま画面のシナリオを「災害モード」に切替え、同じ端末が避難所⇔本部の非常網に早変わりすることを実演（＝平常→有事の自動転用を1本で見せる）。
- 刺さるポイント: 「普段の業務でも毎日役立ち、いざという時は非常網になる」を1デモで伝える。通信費ゼロ・電池駆動も訴求。

### 縦割りデモ（分野別に自分ごと化）
| デモ | 内容 | 刺さる分野（買い手） | 訴求 |
|---|---|---|---|
| 災害対策：避難所⇔本部のAIリレー | 避難所AIが被害・物資要求を要約 → 本部AIが集約・優先度判断。回線全滅想定 | 自治体防災課、消防、DMAT/災害医療、電力/ガス/通信ライフライン | 通信が死んでも指揮系統のAIが動く。BCP・防災訓練予算に直結 |
| インフラ点検：圏外現場のAI連携 | トンネル/ダム/プラント/地下でロボ・ドローン側AIが「異常だけ」要約送信 → 基地AIが記録・指示 | 建設・土木、電力、ガス、鉄道、上下水道、プラント保安 | 圏外でも点検AIと本部AIがつながる。老朽インフラ点検の省人化 |
| スマート農業/畜産：フィールドAI | 圏外の圃場・牧場でセンサ+AIが判断し母屋AIへ要約報告/指示受領。電池駆動 | 農業法人、畜産、林業、農機・JA系 | 広い農地はスマホ圏外でもAIが見守る。スマート農業補助金と好相性 |
| 海・港湾：船上AI⇔陸上AI | 沿岸の携帯圏外で船上AIと陸上AIが交信（漁況・安全・作業指示） | 漁業、海運、港湾、マリンレジャー | 沿岸の“つながらない”を埋める |
| 閉域/セキュリティ：ネット非接続のAI連携 | インターネット非接続でAIエージェント同士が協調（工場OT、重要施設） | 防衛関連、重要インフラ、工場OT/制御系、研究機関 | 外部から侵入されない閉域AI通信（エアギャップ要件） |

### 制作順（推奨）
1. まず **ヒーローデモ「圏外AI会議」** を汎用で仕上げる（使い回し可）。
2. 次に **平常時デモ「毎日使う圏外拠点」** を作り、末尾で「災害モード切替」まで見せる（＝案Aの主軸）。
3. 商談相手が決まったら **縦割りデモ** に着せ替え（中身同じ、シナリオ差し替え）。
4. 最初に狙うのは **平常時運用のある現場（農場・遠隔設備など）**、その延長で **災害対策**（第2弾で **インフラ点検**）。

## 4. 最初の1分野: 災害対策（平常時運用の“有事モード”）

> 位置づけ: 単独の災害専用品ではなく、**案A（平常時運用）で設置済みの基盤を災害モードに切替えたもの**。営業では「普段は日常業務、いざという時は非常網」の二段で見せる。

### ターゲット顧客（誰が払うか）
- 一次: **市区町村の防災課／危機管理課**（地域防災計画・防災訓練・BCP予算）。最初の受注先。
- 二次: **都道府県の危機管理部門、消防本部**（広域・指揮系統で横展開）。
- 周辺: 電力/ガス/水道/通信ライフライン事業者、DMAT/災害医療、社会福祉協議会。
- 入口: 防災展（危機管理産業展 等）出展 ＋ 自治体の防災訓練にデモ持ち込み。

### 殺し文句（そのまま使える）
- 「通信インフラが全部落ちても、AIが指揮を止めません。」
- 「携帯もWi-Fiも衛星契約も無しで、避難所と本部のAIが要点だけ交信します。」
- 「電波が細くてもいい。AIが“要約してから送る”から低帯域で成立します。」
- 「停電しても電池駆動。設置は箱を置くだけ、月額課金なし。」

### デモ台本（訓練・商談でそのまま実演）
1. 机上に2セット設置：「避難所AI端末」と「災害対策本部AI端末」（PC or Raspberry Pi + MLR-429）。
2. 冒頭で LANケーブルを抜き／機内モードON を目の前で実施。画面に「インターネット:OFF」を大表示。
3. 避難所役が自然文で入力：「体育館、避難者120名、水と毛布が不足、透析患者2名」。
4. 避難所AIが要点を要約して電波送信（送信ランプ点灯／ログ表示）。
5. 本部AIが複数避難所からの報告を集約し優先度を判断：「透析患者→最優先搬送」「水◯L・毛布◯枚を配分」。
6. 本部から避難所へ指示を返信。往復が「ネット無しで」成立したことを強調。
7. 距離演出：本部端末を別フロア／屋外に置き、実距離で通ることを見せる。

### 刺さる理由（この分野特有）
- 大災害では携帯基地局・停電・輻輳で通信が真っ先に死ぬという共通認識があり、「ネット無しで動く」の説得力が最大。
- LoRaの長距離・省電力・障害物耐性が、避難所⇔本部という点在拠点の構図に合う。
- AIの要約・優先度判断が、混乱時の情報過多を捌く価値として腹落ちしやすい。

### 想定反論と返し
- 「Starlink/衛星でいいのでは？」→ 月額課金なし・屋内/地下でも可・秒で起動・超低消費電力。衛星の“補完”として併用提案。
- 「電波は免許が要る？」→ MLR-429は429MHz帯の免許不要運用を想定（正確な区分・技適はスペックで要確認。商談前に裏取り）。
- 「通信速度が遅い」→ 遅くて良い設計。AIが要約するので数百文字で足りる。低帯域が前提の強み。
- 「既存の防災無線と何が違う？」→ 人が喋る無線ではなく、AIが判断・集約・指示まで自動化する点が新しい。

### KPI / 次アクション
- ヒーローデモ → 災害版デモに着せ替え（シナリオ差し替えのみ）。
- 自治体1つと防災訓練での実証(PoC)を1件獲得することを最初のゴールに。
- 訴求資料は「1枚：ネット無しでAIが交信する図」に集約。

## 5. 第2弾: インフラ点検（同資産を流用）
- 同じ「圏外でAI同士が要約交信」構造を、トンネル/ダム/プラントの点検AI⇔基地AIに着せ替えるだけ。
- 買い手が民間（電力・鉄道・建設）で継続予算になりやすく、防災で作った信頼を横展開できる。

## 6. オープン事項（要確認）
- MLR-429 の日本での電波法上の区分・技適の正確な扱い（免許不要運用の範囲）。
- 実効通信距離・障害物条件（デモの距離演出の裏取り）。
- 低帯域(19200bps)前提での往復プロトコル設計（要約プロンプト、再送、宛先/複数拠点の扱い）。
- 平常時ユース(案A)の最有力現場の絞り込み（農場/遠隔設備/山小屋など、日次利用の頻度と支払者）。
- 「平常モード ↔ 災害モード」の切替UX（プロンプト/テンプレの持ち方、誤操作防止）。
